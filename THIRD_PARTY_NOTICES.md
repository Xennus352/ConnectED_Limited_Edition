## 1. How this inventory was produced (and its limits)

- **Method:** read the declared dependencies in `package.json` (root, `client`,
  `server`) and resolved versions/licenses from the installed package manifests
  in the pnpm store (`node_modules/.pnpm/**/package.json`).
- **Scope:** direct dependencies for the `client` and `server` workspaces, plus a
  scan of the ~600 resolved packages for notable (non-permissive) licenses.
- **Limits:** this is not exhaustive; transitive dependencies number in the
  hundreds and their `LICENSE` files were not individually captured. Some
  packages declare licenses in array/legacy form and were normalized by hand.
  Versions reflect the current `pnpm-lock.yaml` and may change.
- **What a full audit still needs:** capture each shipped component's full
  license text and copyright notice; resolve the flagged items in §3–§5; and
  review the bundled client output (`client/dist`) for exactly what is
  redistributed.

## 5. Items that could not be verified (and how to check them)

1. **Full transitive license texts** for ~600 resolved packages — run a dedicated
   license scanner (e.g. `pnpm licenses list`, `license-checker`, or an SBOM tool)
   in CI and archive the output with each release.
2. **Exactly what is bundled** into `client/dist` and the server build — audit the
   production artifacts, not just the manifest.
3. **Whether `next`/`sharp`/`@img/sharp-*`** ever reach the shipped artifacts —
   inspect the built output and pruned production install.
4. **Asset provenance** for the images and audio listed in §4 — trace their
   source or replace them.
5. **The Vexels logo's actual license** for the owner's intended use — see Vexels'
   terms or replace the asset.
6. **Any content contributed to the repository** — confirm authorship/rights for
   all code and assets (see `COMMERCIAL_LICENSE.md` §"Ownership verification").
